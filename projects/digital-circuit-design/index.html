01Objective

Overview

The project started from the problem that maternity badges are small, so pregnant passengers are often not offered priority seats. We designed the seat so that, when a phone connects to it over Bluetooth, an LED under the seat lights for 5 seconds and a display shows the number of pregnant passengers in the car.

03Troubleshooting

Troubleshooting

  • Tied the NE555 trigger (pin 2) and threshold (pin 6) together to the RC network and drove the LED through logic gates, changing to a circuit that lights automatically for only 5 s without a switch
  • The state pin of the HC-06 did not output the connection state properly, so the module was replaced with an HC-05, whose state pin reports whether a phone is connected
  • Running two Arduinos and the circuit on separate supplies caused malfunctions, so the grounds of the three supplies were tied together and a battery delivering a stable 5 V was used

01Objective

Overview

We implemented a four-floor elevator with logic ICs. It compares the current floor with the requested floors to decide whether to go up, stop, or go down, and it gives priority to upward requests while moving up and to downward requests while moving down.

  • Assigned a processing time to each floor considering travel and door opening and closing time
  • Blocks the request signal through an infrared sensor if the user leaves for more than 1.5 s after pressing the button, and through a pressure sensor if the load exceeds capacity
  • Calculates the expected arrival time and shows it on a 7-segment display (relative to the 1st floor)

Circuits

03Troubleshooting

Troubleshooting

  • The current floor was stored as a one-hot code, so only the 1st floor had to be preset at power-on. With a 1 s monostable, the preset was released before the circuit stabilized, so only the 1st-floor preset was changed to a 2 s monostable
  • The 1 s high of the stop signal varied with the flip-flop clock, so it was fixed to 1 s with an NE555
  • The expected-time down counter wrapped around to 9 instead of stopping at 0, and digits were skipped because of the asynchronous reset, so it was modified to reset when output 9 (1001) is detected
  • Reverse voltage from the counter dropped the overall VCC by 2.5 – 3 V. This was blocked with a diode, and the resulting voltage drop was handled by using a 1 s clock from a function generator instead
PARKING SYSTEM

Automatic Parking Assignment System

Electronic Materials Laboratory and Design 1
Team

01Objective

Overview

For a six-slot lot (2 accessible, 2 regular, 1 EV, 1 compact), we set priorities for six cases by vehicle type and disability status, and designed an assignment system that also handles unexpected events such as a slot freeing up on the way, an assigned slot being taken, and shaded slots in summer.

02Approach

System Design and Circuits

System design

  • Split the system into a Controller (8-state FSM) and a Datapath (9 blocks), organized the state transitions with an ASMD chart, and divided the parts among the team
  • Implemented the basic operation in Verilog first and shared it, and verified operation with Verilog and PSpice before building
  • In response to feedback at the proposal presentation (too few unexpected cases), extended the design with a FAIL signal and a re-search from the current position

Circuits

03Troubleshooting

Troubleshooting

  • Voltage drop during implementation was solved with two power-supply channels and AND gates
  • A polarity mismatch between active-low parts and the design was solved with a compensating circuit

NAVIGATION

Shortest-Time Route Navigation

Semester
2025-2
Course
Electronic Materials Laboratory and Design 2
Team
3
Role
Member
01Objective

Overview

This system searches for and selects the fastest route to the destination among bus, transfer, and walking routes, using an ASMD-based FSM and datapath.

02Approach

System Design and Circuits

System design

  • The Controller encodes 15 states in one-hot, and the current position is stored as a 16-bit one-hot code (blocks 0 – 15)
  • Counters in the datapath search up and down from the current position at the same time to find the nearest stop, and compare the arrival times of buses coming to that stop
  • Compares the total travel time of bus-only, transfer, and all-walking routes to choose the shortest, and stores the stops and walking segments in registers
  • Handles unexpected events: after an accident, the passenger leaves the bus and the route is searched again, and under congestion the bus weight is replaced with the congestion value

Circuits

03Troubleshooting

Troubleshooting

  • With about 14 breadboards, voltage drop broke down the signal levels, so buffers were added and power was split across several supplies
  • Using several clocks misaligned the signal timing, so the bus, pedestrian, and delay clocks were synchronized and the Controller was modified to generate clocks only in action states
  • Creating a separate state for every action made the Controller too large, so it was optimized by building small controllers from counters inside states
